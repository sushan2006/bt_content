# 4. AUTHENTIC PIXEL-ART DESIGN SYSTEM

Treat the aesthetic as intentional low-resolution illustration, not high-resolution vector graphics with a pixelation filter slapped on top.

Each drawn pixel is a design decision. Silhouettes, hue changes, shading clusters, outlines, and highlights must remain coherent at the native internal art resolution.

## Suggested starting palette

Use a curated subset of these as a flexible starting palette; adjust or substitute where the actual topic requires a different mood:

- Midnight navy: `#141528`
- Ink purple: `#282B4D`
- Dark plum: `#433762`
- Electric blue: `#4A86D4`
- Aqua: `#73D9C9`
- Bright mint: `#A7F4C2`
- Coral: `#F47E74`
- Warm orange: `#F5AE69`
- Gold: `#F8D46D`
- Pale highlight: `#F2F0DA`

Use tightly related tonal ramps rather than randomly assigning unlimited RGB colors. A limited palette must still permit clear focal elements, precise visual explanations, and intentional color coding.

Use dark regions to organize bright accents. Keep major text and information cards legible against the environment. Vary the palette across compositions only when there is a coherent visual reason.

## Pixel clusters and outlines

- Build readable shapes from intentional pixel clusters rather than isolated random dots.
- Favor coherent contours and controlled staircase diagonals.
- Use interior color clusters to indicate material, volume, and light direction.
- Apply consistent outline thickness when the chosen substyle needs outlines.
- Keep highlights and shadows on the same logical pixel grid as the artwork.
- Avoid noisy single-pixel dithering across every surface.
- Concentrate small details near important objects; simplify distant elements.
- Use silhouettes that remain recognizable at a glance, even on a small playback screen.

## Shading and material finish

Use small stepped tonal bands, chunky highlights, simplified ambient shading, and occasional structured dither patterns.

Do not rely on conventional smooth gradients or blurred glow as the main material shading. When atmosphere or light is necessary, translate it into stepped color bands, ordered dithering, stylized pixels, or carefully controlled full-resolution composite effects that do not soften critical pixel edges.

Use the right level of detail for each object. Give important central forms more attention than incidental background scenery.

## Foreground, middle distance and background

Create layered compositions with clearly distinct spatial planes.

Use tile-like patterns and modular scenery where they enhance the piece, but avoid making every composition look like a scrolling game level.

Foreground objects may overlap diagram elements, reveal hidden information, or frame camera motion. Distant layers should remain less detailed and less contrasty than the subject.

Use parallax deliberately and maintain pixel coherence as layers move.

# 6. CINEMATIC MOTION WITHOUT BLURRING PIXELS

## Direction and focus

# 11. PROCEDURAL PIXEL-ART RENDERING ARCHITECTURE

Build a reusable pixel-art drawing and animation engine directly inside the HTML Artifact.

Use standard browser technologies:

- JavaScript, HTML and CSS.
- HTML5 Canvas 2D for pixel-native illustration and compositing.
- SVG or WebGL where they offer a concrete benefit without blurring or changing the aesthetic.
- Browser-compatible JavaScript libraries when genuinely useful and accessible.
- Web Audio API for enabled audio.
- Browser-supported video encoding and download APIs.

Do not rely on an external game engine, prebuilt pixel sprite pack, AI-generated images, video templates, desktop tooling, a terminal, or a separate build system.

## Low-resolution master canvas

Draw the main artwork onto a logical low-resolution offscreen Canvas with the same aspect ratio as the configured output.

For the default output, a well-chosen integer scale can map low-resolution art pixels into equally sized blocks at the final exported resolution. For other formats or resolutions, compute the internal size and scaling strategy from configuration.

Favor an integer upscaling factor when possible. Preserve the output's exact aspect ratio without distorting sprites or characters.

Do not hardcode the internal Canvas dimensions independently of the selected final resolution.

## Nearest-neighbor enlargement

When compositing the logical art surface onto the export Canvas:

- Disable image smoothing with `imageSmoothingEnabled = false`.
- Use nearest-neighbor drawing for pixel imagery.
- Keep drawing and scaling coordinates correctly aligned to the source grid.
- Use CSS `image-rendering: pixelated` or `crisp-edges` for the browser preview where suitable.
- Preserve clean edges in the actual encoded frames, not just the scaled HTML preview.

Avoid applying anti-aliasing or bilinear filtering to the final pixel-art surface.

## Sprite construction

Generate original raster sprites with programmatic primitives, small pixel maps, tile data, masks, procedural patterns, or cached sprite atlases.

Use sprite sheets or animation-pose caches for repeating actions. Avoid rebuilding an entire complex sprite in JavaScript every frame if a cached representation would suffice.

Keep assets and scene functions reusable across compositions.

## Tiles and patterns

Use repeatable tile forms when they reinforce the artwork, but vary local details intelligently so large environments do not look copy-pasted.

Cache static patterns. Use seeded, well-mixed randomness for stable procedural details.

Do not generate new random noise or re-roll tile appearance each frame.

## Layers and composite

Maintain an explicit render order: background, middle distance, main illustrations, important effects, explanatory diagram elements, typography, overlays and subtitles when enabled.

Every essential element must be drawn into the captured video surface. Do not rely on HTML overlays that appear in the preview but disappear from exported media.
